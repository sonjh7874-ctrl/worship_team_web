# README 화면 캡처 가이드

공개 README에 사용할 실제 서비스 화면의 파일명, 촬영 조건과 개인정보 점검 기준을 정리한다.

## 저장할 화면

| 파일명 | 화면 | 권장 크기 | 촬영 조건 |
|---|---|---|---|
| `home-mobile.png.jpg` | 모바일 홈 | 원본 | 비로그인 상태의 콘티·스케줄·공지 요약 |
| `conti-mobile.png.jpg` | 모바일 콘티 | 원본 | 곡·키·송폼과 과거 콘티 목록 |
| `schedule-mobile-cropped.png` | 월간 스케줄·마이크 배치 | README 편집본 | 실제 배정이 있는 4주차 카드 중심으로 원본을 축약 |
| `calendar-mobile-cropped.png` | 캘린더 | README 편집본 | 하단 선택일 카드를 제외하고 월간 달력까지 표시 |
| `conti-review-mobile.png.jpg` | AI 콘티 입력 | 보관용 원본 | 인식 결과 검수 화면이 아니라 README 대표 이미지에서는 제외 |

최종 파일은 이 디렉터리에 저장한다. 원본 해상도를 유지하되 PNG 압축 후 파일당 1MB 안팎을 권장한다.

## 개인정보 점검

캡처하기 전에 다음 항목을 모두 확인한다.

- 실제 팀원 이름, 생년월일, 이메일이 보이지 않는다.
- 실제 참·불참 사유나 개인 일정이 보이지 않는다.
- 악보·가사처럼 저작권이 있는 원문이 읽을 수 있는 크기로 노출되지 않는다.
- 브라우저 주소창, 개발자 도구, 환경변수와 API 키가 보이지 않는다.
- 테스트 계정 이름과 댓글은 가명으로 통일한다.
- 공개 서비스에 남아 있는 실제 데이터 대신 별도 가명 데이터로 촬영한다.

## README 배치 순서

공개 README에는 홈·콘티·월간 스케줄·캘린더를 2열 표로 배치한다. AI 콘티 이미지는 실제 인식 결과와
검수 보조 UI가 함께 보이는 화면을 새로 촬영했을 때 교체하거나 추가한다.

이미지가 준비되기 전에는 README에 깨진 이미지 링크나 임시 목업을 넣지 않는다. 실제 화면이 아닌 생성형
이미지를 제품 스크린샷처럼 사용하지 않는다.
