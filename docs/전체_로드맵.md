### Phase 1 — 콘티 기능 마무리 ✅ 완료 (2026-08-19)

README 원칙상 "화면 하나로 연습 가능"이 목표이므로, 지금 만든 껍데기에 다음을 채웁니다.

- 곡 마스터(`songs`) + 콘티-곡 배치(`PUT /contis/{id}/songs`, 배열 통째 교체)
- 악보 PDF 업로드 (Supabase Storage 연동, `sheet_files`) — **선행 필요**: Storage 버킷(`sheet-files`) 생성
- 콘티 수정/삭제(`PATCH`/`DELETE`)
- Frontend: 콘티 상세 페이지(`/conti/12`), 과거 콘티 목록
- **여기서 결정 필요한 것**: 상세 페이지 이동을 위한 라우팅 라이브러리(`react-router` 등) 도입 여부 — 지금까지는 페이지 하나만 고정 렌더해서 미뤄뒀던 부분
- Phase 1 잔여 작업 분해
    
    ### 1. 곡 마스터(songs) API
    
    **사양**: API명세 1-2 그대로 — `GET /songs?q=`(검색), `POST /songs`, `PATCH /songs/{song_id}`. 인증은 POST/PATCH만 편집 비밀번호.
    **신규 파일**: `backend/app/schemas/song.py`, `backend/app/repositories/song_repository.py`, `backend/app/services/song_service.py`, `backend/app/routers/songs.py`**수정 파일**: `backend/app/main.py` (라우터 등록)
    **확인 방법**: `/docs`에서 3개 엔드포인트 호출 테스트
    
    ### 2. 콘티-곡 배치 저장 API
    
    **사양**: API명세 1-3 — `PUT /contis/{conti_id}/songs` (배열 통째 교체), `DELETE /contis/{conti_id}/songs/{order_no}`. `song_id` 없이 `new_song`이 오면 서버가 곡을 먼저 생성(1번 API 재사용) 후 배치.
    **의존**: 1번 완료 후
    **수정 파일**: `backend/app/schemas/conti.py`(요청 스키마 추가), `backend/app/repositories/conti_repository.py`(배치 교체 함수), `backend/app/services/conti_service.py`(신규곡 생성+배치 로직), `backend/app/routers/contis.py`(PUT/DELETE 엔드포인트)
    
    ### 3. 콘티 수정/삭제
    
    **사양**: API명세 1-1 나머지 — `PATCH /contis/{conti_id}`, `DELETE /contis/{conti_id}`**수정 파일**: `backend/app/schemas/conti.py`(ContiUpdate), `backend/app/repositories/conti_repository.py`(update/delete 함수), `backend/app/services/conti_service.py`, `backend/app/routers/contis.py`
    
    ### 4. Supabase Storage 연동 + 악보 파일 업로드
    
    **사전 준비(사용자 액션 필요)**: Supabase 대시보드에서 `sheet-files` 버킷 생성(Private) — 이건 콘솔 작업이라 내가 대신 할 수 없음
    **사양**: API명세 1-5 — `POST /contis/{conti_id}/files`(multipart), `DELETE /files/{file_id}`. 콘티 상세 조회 시 서명 URL(1시간) 발급해 응답에 포함.
    **신규 파일**: `backend/app/repositories/sheet_file_repository.py`**수정 파일**: `backend/app/supabase_client.py`(Storage 헬퍼), `backend/app/schemas/conti.py`(SheetFileItem에 url 필드 추가), `backend/app/services/conti_service.py`(get_conti에서 서명 URL 발급), `backend/app/routers/contis.py`(파일 업로드/삭제 라우트)
    
    ### 5. 프론트 라우팅 도입
    
    **사양**: `react-router-dom` 설치, `/`(메인) `/conti/:id`(상세) 라우트 구성
    **신규 파일**: 없음
    **수정 파일**: `frontend/package.json`, `frontend/src/main.jsx` 또는 `App.jsx`(`BrowserRouter` 적용)
    
    ### 6. 프론트 — 콘티 상세 페이지 + 과거 목록
    
    **사양**: README 흐름 — 메인에 최신 콘티, 하단에 과거 콘티 목록(클릭 시 `/conti/:id` 이동), 상세 페이지는 메인과 동일한 상세 컴포넌트 재사용
    **의존**: 5번 완료 후
    **신규 파일**: `frontend/src/pages/ContiDetail.jsx`, `frontend/src/components/ContiDetailView.jsx`(메인/상세 공용 컴포넌트로 분리 추천)
    **수정 파일**: `frontend/src/pages/ContiMain.jsx`(과거 목록 추가 + 공용 컴포넌트로 리팩터), `frontend/src/App.jsx`(라우트 정의)
    
    ### 7. 프론트 — 비밀번호 헤더 지원 API 클라이언트 확장
    
    **사양**: `apiPost`/`apiPut`/`apiPatch`/`apiDelete` + `X-Edit-Password` 헤더 지원 추가
    **수정 파일**: `frontend/src/api/client.js`, `frontend/src/api/contis.js`(createConti, updateConti, deleteConti, putContiSongs 함수 추가)
    
    ### 8. 프론트 — 콘티 작성/수정 폼(곡 배치 편집)
    
    **사양**: 리더십이 곡 목록을 입력/수정하고 비밀번호 입력 후 저장(`PUT /contis/{id}/songs` 호출)
    **의존**: 2, 7번 완료 후
    **신규 파일**: `frontend/src/pages/ContiEdit.jsx`**수정 파일**: `frontend/src/App.jsx`(라우트 추가)
    
    ### 9. 프론트 — 악보 업로드 UI
    
    **사양**: 콘티 상세/수정 화면에 PDF 업로드 폼
    **의존**: 4, 8번 완료 후
    **수정 파일**: `frontend/src/pages/ContiEdit.jsx` 또는 `ContiDetail.jsx`, `frontend/src/api/contis.js`(uploadSheetFile)
