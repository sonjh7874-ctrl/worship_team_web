### Phase 2 — 공지사항 + 월간 스케줄 (기능 2, 기본 CRUD)

- **선행**: 인명부(`members`) CRUD — 스케줄 배정 드롭다운의 전제 데이터라 이 단계 안에서 먼저 처리

- 월간 스케줄 CRUD — `schedule_assignments`(세로형) 저장 + 조회 시 화면용으로 피벗해서 응답하는 서비스 로직
- Frontend: 공지 목록/상세, 월별 스케줄 조회 화면
- Phase 2 작업 분해 (SDD)

    ### 6. 월간 스케줄 백엔드 — 배정(schedule_assignments) 저장 + 피벗 응답
    
    **사양**: API명세 2-2/2-3 — `PUT /schedules/{id}/weeks/{week_id}/assignments`(전체교체, `conti_songs`와 동일 delete-then-insert 패턴). 조회(`GET /schedules`)는 세로형 데이터를 서비스 레이어에서 API명세 예시처럼 `instrument.{key1,...}`, `singer.mic.{1~8}`, `singer.choir[]` 형태로 피벗해 반환.
    
    **의존**: 5번 완료 후 (같은 파일들 확장)
    
    **수정 파일**: `backend/app/schemas/schedule.py`(배정 요청/응답 모델 추가), `backend/app/repositories/schedule_repository.py`(`replace_assignments`), `backend/app/services/schedule_service.py`(피벗 변환 함수 — positions 코드별로 그룹핑), `backend/app/routers/schedules.py`(PUT 엔드포인트)
    
    **검증 포인트**: `member_id`/`name_snapshot` 중 하나 필수(400), 단일 슬롯 포지션 중복 배정 시 400 — DB 제약과 별개로 API 레벨에서도 사전 검증 (API명세 2-3 명시 사항)
    
    **확인 방법**: 마이크 1~8 + 콰이어 2명 배정 저장 → 조회 시 피벗된 JSON이 API명세 예시와 같은 모양인지 확인

    **신규 파일**: `frontend/src/pages/ScheduleEdit.jsx`(주차 배정 입력 폼)
    **수정 파일**: `frontend/src/pages/ScheduleMain.jsx`(빈 파일에 구현 — 연/월 셀렉터 + 주차 목록), `frontend/src/api/schedules.js`, `frontend/src/App.jsx`(`/schedules`, `/schedules/:id/weeks/:weekId/edit` 라우트)
